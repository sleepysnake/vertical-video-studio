# 口播批量生产工作流（2026-10-04，字幕分析版本 19）

## 数据流

```text
源视频 → FFmpeg 提音频 → 百炼 ASR（词级时间戳）
       → 本地检测音轨静音，整理 ASR 全文、原句及词时间戳
       → 文本 API 结合全文提出剪辑初稿
       → 独立文本 API 请求语义复审全文及初稿，输出最终计划 JSON
       → 将最终模型词范围与所选停顿映射为可执行时间线
       → 文本 API 校对实际保留词并按语义生成字幕
       → 保留 token 按顺序覆盖一次、源时间映射与字幕排版检查
       → FFmpeg 按同一时间映射处理原声和画面、套模板、烧录字幕
       → 音视频流与时长质检 → 成片及执行记录
```

本程序独立调用用户配置的 ASR 和文本模型 API，不需要 Codex、ComfyUI 或本地 Whisper。ASR 上传、异步提交、轮询、下载原始转写及缓存复用保持原流程。生产数据流为 `flow_version=4`，字幕缓存版本为 `19`，执行计划为版本 `6`、`mode=model_authored`。文本模型读取转写和时间索引，不直接接收音视频。

初稿、语义复审和字幕请求携带 `full_transcript` 全文背景。初稿读取句子、可编辑源词范围、词索引与时间及静音候选；复审读取全文与初稿，检查遗漏、过度删除、共同主语与动词、概括和例子、重说及强调，给出最终 JSON。复审是当前配置文本模型的独立请求，不要求第二个服务或 Key；它不听音，不是声学复审。普通预算内素材通常有初稿、复审和字幕三次请求；较长素材按预算分章，章节只限制输入大小，不决定删除内容。

达到压缩阈值的长词列表发送前转为带列名的行表：剪辑阶段使用 `word_table`，保留原词索引、文字和起止毫秒；字幕阶段使用 `token_table`，保留字幕 token、原词索引、文字和时长。原始时间戳和完整记录仍在本地，由程序映射切点和字幕时间。压缩减少重复 JSON 字段，全文背景及模型修复提示仍保留。

先由最终模型计划确定原声裁剪，字幕阶段只接收实际保留词，不再增删音频。字幕可清理不承担意义的口头干扰，但对应 token 和时间仍全部纳入字幕范围。章节、格式修复及网络重试会增加请求数量，实际调用见 `model-calls.json`。

## 模型判断与技术执行

模型负责判断废弃改口、起句、重录式重说、口癖、强调和停顿是否应删。独立语义复审可改变初稿，最终 JSON 包含 `cuts`、`pause_compressions`、`display_only_suggestions`、`uncertain`、`review_changes`。这些判断是否符合原意不能由索引或时长检查证明，实际效果仍需核对回复及成片。

当前生产不使用旧单次 12 秒、总体 40%、最短剪切 0.2 秒、最短保留 0.18 秒、词表或“短于 1 秒只能改字幕”等政策否决模型选择。旧 `Strategy` 字段、`build_edit_plan` 及旧策略函数保留作兼容；旧函数的测试和历史输出不代表当前生产逻辑。原声语义判断仍有提示词规范，但代码只验证实际源词、源时间、字幕映射和媒体可执行边界。

初稿、复审、字幕提示词分别为 `config/edit_prompt.txt`、`config/review_prompt.txt`、`config/caption_prompt.txt`，使用文本编辑器修改配置文件，界面不提供提示词编辑入口。每批固定快照，改提示词使文本缓存失效但保留有效 ASR。实际提示词保存为 `prompts-<摘要>.json`。提示词不能绕过技术执行校验，软件也不会自动从结果学习。

最终计划的定位约定：

| 字段 | 含义与执行 |
| --- | --- |
| `start_word` / `end_word` | 整数全局源词索引，区间含首不含尾，代码从原 ASR 取时间 |
| `kind`、`reason`、`joined_text` | 模型的分类、依据和接续说明，不由固定词表重新分类 |
| `replacement_range` | 模型对替代表达的语义注释，代码不以该注释与其它选择的冲突否决最终决定 |
| `end_before_word` | 需要连同废弃表达后的气口剪掉时显式设置，须等于 `end_word` 并指向紧邻下一源词 |
| `keep_before_ms` | 上述 CUT 在下一词前保留的空白，默认 120 毫秒；没有延长字段时不自动扩展 |
| `pause_compressions.gap_id` | 选择 `S1` 等实际静音候选，未选中的候选不执行 |
| `keep_before_ms` / `keep_after_ms` | 静音候选两端留白，默认各 120 毫秒 |

代码验证索引属于当前可编辑范围、原词时间有限且有效、映射不越过源视频边界、切点不侵入最终未选择删除的源词。重叠 CUT 机械合并，避免重复删除时间；至少保留可输出画面。仅有估算时间时不能执行准确裁剪。ASR 没有准确字级时间时，不能用字符均分强行切词内发音，可选整词删除或交给字幕修整。

本地检测音轨只提供确认静音候选，不自动加入长气口、首尾空白或词表口癖裁剪。模型选择的静音区间还要扣除未选择删除的源词并应用留白，不能借静音候选切掉保留讲话。起句后的气口延长同样必须由最终 CUT 显式选择，代码不按停顿阈值自行扩大区间。

`model-edit-plan.json` 保存初稿、复审最终 JSON 及修改记录；`review-attempts.json` 保存复审回复与失败原因。`edit-plan.json` 是版本 `6` 的执行时间线，记录模型选择、实际 CUT、所选静音和未删除源词检查；`processing_summary` 汇总实际执行结果。数量和时间统计不是语义效果评分。

## 字幕与回退

字幕模型结合全文和最终保留 token，纠错、清理口头干扰并按意群分句。代码不以 1 秒文字清理上限或文字相似度 0.55 判断改文是否合理；事实、否定、数量、概括和强调的保留要求写在模型提示词中。索引必须有效，保留 token 按原顺序恰好覆盖一次，字幕起止取自实际源词。技术映射通过不证明字幕语义正确。

字幕目标每条 10–14 字，最长排版目标 16 字，不能机械切机构名、姓名或紧密词组。超长输出先请求模型重新分句；仍过长时仅局部排版修整，保留其他模型字幕。不能可靠映射的单条回退原文，结构或覆盖仍整体无效时才组级回退。局部恢复不新增原声删除，也不按文字长度生成发音时间。

程序检查所有实际保留的口语词按源顺序恰好覆盖一次，不能漏词、重叠或重排。局部排版修整不决定裁剪、不删除新原声，也不能为缩短字幕省略事实或独有信息。ASR 可能把冒号等独立标点放进词列表，程序保留其原词索引用于剪辑定位，但字幕生成和覆盖校验均不把独立标点当作口语词；数字、单位和其他实际保留语音仍必须覆盖。`coverage_audit` 记录 `captionable_words`、`punctuation_only_word_indices` 与按顺序一次覆盖的结果。标点和空白规范化，分句语义由模型决定。

`captions.json` 的 `caption_formatting_repairs` 保存原模型文字、处理后的字幕及是否局部原文回退；`processing_summary` 另记录最终字幕数、原文回退条数和排版修整数。需要核对原文回退条数，不能只凭存在某个 `caption_fallback_groups` 组号就认为整组模型文字都丢失。

模型输出修整文字后，字符省略记录由文字差异建立，兼容旧 `display_cleanup`；这份记录不产生新的音频切点。索引、映射和排版问题写入 `uncertain`、`caption-attempts.json` 与 `coverage_audit`。运行时提示词使用通用规范，样片具体台词只保留在回归文档中。

修整后 token 仍全部纳入字幕范围，字幕起止时间不因为少一个重复字而缩短。`caption_timeline.json` 记录修整原文、原片时间、成片时间、`audio_kept: true` 和估算方式。ASR 错字纠正仍是独立功能。

文本接口的超时、429、部分 5xx、空内容和截断 JSON 有有限重试。无法取得有效 JSON 时停止本次任务，保存失败记录，不标记阶段完成。初稿、复审和字幕进度保存到 `captions.partial.json`，相同配置只重试未完成阶段；复审未完成时不先生成最终字幕或将初稿冒充最终计划。

`edit-attempts.json`、`review-attempts.json`、`caption-attempts.json` 分别记录初稿、复审、字幕结果和失败原因；任务中断时检查点保存已有尝试。`model-calls.json` 记录阶段、每次 HTTP 尝试、输入字符数、正文和思考内容长度、结束原因及服务实际返回的 token 用量。日志不含 Key 或思考正文；最后一次超时不掩盖前次 `length` 截断。`runs.json` 记录结果、耗时和请求数，不估造费用。

Qwen3.7 系列按原有适配关闭思考；百炼官方接口上的 `deepseek-v4.1-flash`、`deepseek-v4-pro`、`deepseek-v4-flash` 也按服务约定关闭思考，直接生成 JSON。自定义服务和其他型号不自动套用这组 DeepSeek 参数。此适配和输入压缩减少不必要的响应开销，但不保证请求不会截断、超时或产生错误判断。

ASR 任务 ID 与原始转写单独保存，未变化素材可以继续查询或直接复用。版本 `19` 使旧文本及阶段缓存失效，重新执行初稿、复审和字幕，ASR 不随文本版本失效。相同配置重试恢复已完成阶段；“重新导出所选”只复用已有执行时间线、字幕和新样式，不调用模型，不需要 Key。也支持环境变量 `DASHSCOPE_API_KEY`。

每次尝试有独立 `run_id`，完成或被本次采纳的 `edit-plan.json` 使用相同 ID，`runs.json` 中的 `plan_ready` 和 `plan_path` 指向本次可用计划。结果详情只展示与本次匹配的计划；未生成可用计划时明确提示。无 ID 的历史记录按任务时间与计划修改时间判断，旧计划仅作为历史路径显示，不展开为本次复核点。建议复核表示候选已保留原声，不是任务失败的原因。

## 验证范围

本轮没有可用用户 Key，未发起新在线模型请求。离线 HTTP 模拟、历史计划 JSON 重放和 FFmpeg 检查可以证明调用顺序、源词定位、缓存恢复及媒体执行，不证明新的语义复审效果。历史用户回复的遗漏和过度删除不会因技术校验通过而自动消失；关闭思考是否影响判断尚未做同模型 A/B 验证。真实运行需核对初稿、复审最终计划与成片，不承诺达到固定删除量或 5 分 06 秒。

执行边界重放中，旧 API 的 14 处 CUT 均被编译执行，共 16.16 秒；认可方案的 10 处 CUT 与 2 处明确选择的停顿共 23.831875 秒，753 个保留源词均未被切点侵入。重放没有调用 API 或生成新成片，ASR 继续复用。它证明旧策略不会再拦截这些结构合法的计划，不能证明旧候选语义正确，也不能证明新模型会提出认可方案。


## 渲染与质检

声音按保留源区间独立拼接；画面依照相同删除区间重算时间并保持原帧率，字幕用同一源片到成片映射重定位。此实现避免组合音视频分段拼接时，视频帧舍入逐段填充声音造成累计漂移。所有保留词都检查不与切点相交；不足 20 毫秒的保留时间也不会被区间计算静默丢掉。`caption_timeline.json` 保存源词、源时间、成片时间和保留区间，便于检查字幕与实际裁剪关系。

右侧模板预览会显示单视频或批量当前选中视频的画面，按成片视频区域的比例居中裁切。时间滑杆用于选择原片时刻；文字、姓名条及区域调整即时叠加，便于检查人物是否被遮挡。预览显示原视频帧和当前排版，不带声播放，也不是已剪辑成片的时间线。区域提示框分别以红色、橙色、绿色显示视频、主题和自定义姓名条区域；框选后即使主题文字为空也显示区域。这些提示框不进入成片。

主题可设置字体、文字颜色，以及自动字号或手动 12–300 像素字号，像素按成片尺寸计算。普通文字、描边文字、柔和阴影、轻微立体、双色渐变五种效果，可与无背景、矩形背景、圆角背景、胶囊背景、斜边背景五种样式组合；背景颜色、不透明度、渐变副色、描边颜色和粗细可配置。自动字号按主题区域适配；手动字号不会静默缩小，换行后仍超出区域时提示减小字号或扩大区域。预览和成片共用主题绘制逻辑。设置保存到本机，并写入 Edit Plan 的 `template.topic_style`；它不参与文本缓存摘要，已有任务只需“重新导出所选”即可应用新样式，不调用 ASR 或文本模型。文字配置的功能组织参考 [CapCut 官方介绍](https://www.capcut.com/resource/adjust-text-spacing-and-layout-in-videos)。

姓名条整体大小为 25%–200%，同时缩放底图和文字；也可自定义 `nameplate_box` 框选位置和尺寸，整张姓名条保持比例居中放入该区域，区域模式下百分比控件停用。清空自定义区域后恢复百分比控制。大小和区域保存到本机设置及 Edit Plan 的模板快照，不参与文本缓存摘要，因此仅调整位置或大小不会重调 ASR 或文本模型。CLI 渲染支持 `--nameplate-scale` 和 `--nameplate-box`。

“字幕样式”提供文字颜色、自动或手动字号、字体、描边颜色和粗细，保存到本机设置并随每批任务固定。默认白字黑描边；手动字号不缩小，最多换为两行；放不下则提示减小字号。样式快照写入 Edit Plan 的 `template.caption_style`，不参与文本阶段缓存摘要，因此只换样式不会再次调用 ASR 或文本模型。命令行渲染也支持 `--caption-color`、`--caption-size`、`--caption-font`、`--caption-outline-color`、`--caption-outline-width`。

输入模板尺寸决定输出画布尺寸。默认编码档为 H.264 CRF 23、AAC 128k，可切换高画质或小体积。默认对原片抽取三个画面，计算上方中心区域的亮度中位数；低于用户设置的标准值超过 12 才提亮，正常画面保持原样。测量值和决定写入 `brightness.json` 与 Edit Plan。人物画面的手动提亮、压暗仍可选，模板颜色不随之变化。姓名条提供经典蓝色、简洁白字、深色底条、蓝色斜边、青绿渐变、深蓝金线和浅色简约，界面预览与导出共用绘制函数；主题文字仅在设置主题区域后叠加。视频区域可自动识别透明模板的空白；红框可拖动、用边缘控制点调整大小。

生产质检只核对视频流、音频流和计划成片时长，不再添加删除比例或短保留片段策略提示。结果保存为 `qc.json`；详情显示本次任务的模型计划、执行统计、疑点及局部回退，失败先显示真实错误。全流程不要求中途人工确认。

每条工作目录保存 `transcription.json`、`sentences.json`、`model-edit-plan.json`、`edit-attempts.json`、`review-attempts.json`、`caption-attempts.json`、`edit-plan.json`、`captions.json`、`captions.rendered.json`、`caption_timeline.json`、`model-calls.json`、`qc.json` 和 `runs.json`。

## 可选二次编辑

自动流程不要求人工操作。文件列表上方的“编辑所选字幕”打开字幕表格，支持改文字、成片起止秒数、拆分、合并、删除字幕和恢复自动字幕；原始识别文字供参考。“保存字幕”另存 `caption-overrides.json`，保留自动字幕及前一次修改备份，不直接改变旧 MP4。“保存并重新导出”或“重新导出所选”调用纯渲染路径，复用原视频、ASR 时间戳和已有剪辑，不需要 API Key、不调用模型、不重新检测静音。手动时间由成片时间映射到原视频时间，并保存新 `caption_timeline.json`，原声和画面剪辑不改变。原视频变化时拒绝使用旧剪辑；自动字幕或剪辑计划变化时旧手动字幕不自动套用，旧修改文件仍保留。字幕编辑窗口仍不支持带声片段播放；主窗口的时间滑杆可查看原片静态帧及排版。当前不支持持久化调度队列、黑屏或音量检测。
